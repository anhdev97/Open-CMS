# Style system: columns, spacing, size and colors — design

Date: 2026-11-24 · Status: draft for approval · Phase 1 of 3 (2: shared Header/Footer regions, 3: Menus)

## Intent

Building a header, footer or marketing section by drag and drop in the block builder is hard today: a Box has one
padding token and 7 background colors; Columns are 2–4 equal columns; nothing sets margin, width, height, per-side
spacing, text/border color, radius, or per-screen behaviour. The goal is that a developer (and later a less technical
user) can lay out a real site header — logo | menu | actions, menu hidden on mobile — and a brand-coloured footer
or hero without writing code, and that the result still reads as one design system.

Test target: the user's mockup `docs/superpowers/specs/assets/2026-11-24-store-preview.html` (my-store editorial
storefront). Rebuilt in `examples/my-store` with the builders only, no hand-written block code:

- Header: wordmark left, nav right (`space-between`), min-height 76px, padding 14px 5%, bottom border only;
  on mobile stacks vertically.
- Hero: 2 columns `2fr 3fr` (ratio switchable 40/60 · 50/50 · 60/40), copy column vertically centred, image fills
  its column (cover, min-height 450px); 1 column on mobile, image 3:2.
- Featured products: section head (title ↔ link, space-between), 3-column grid, 2 on mobile.
- Story: `2fr 3fr` on a feature-colored band.
- Footer: accent background, `2fr 1fr 1fr`; on mobile 2 columns with the intro spanning both.
- Palettes: the whole site switches between 3 palettes (olive, clay, night) of the same 6 named colors
  (surface, feature, ink, accent, accent-ink, line).
- Hero/product image: the user's `store-editorial.png`, uploaded to the media library by the seed.

## Goals

- Columns from a 12-unit model with ratio presets and custom tracks (`fr`, `auto`, fixed length), set per breakpoint.
- Per-side padding and margin, width / max-width / height / min-height, hide per breakpoint.
- Colors: the 7 semantic tokens + project brand colors declared in code + custom hex.
- Palettes: a project declares several palettes giving values to the same brand color names; one is active.
- Background, text color, border (width, color), radius.
- Every value: pick a design token by default, or "Custom" for a free value (decided: approach C).
- Edits target a breakpoint chosen with the device toggle (Mobile / Tablet / Desktop); unset breakpoints inherit
  from the smaller one (mobile-first).
- Existing composed blocks, page data and library blocks keep rendering unchanged.

## Non-goals

- Font families and fluid type (the mockup's serif display font stays project CSS), `clamp()` values,
- Hover / focus / animation styles, background images and overlays, gradients, typography scale beyond what Heading
  and Text already have, dark-mode variants of brand colors. (Candidates for a later phase.)
- Header/Footer regions and Menus (phases 2 and 3).
- Free CSS text or class names typed by the user.
- Known limit: the my-store wordmark serif relies on structural CSS selectors in its `globals.css` (no font control
  yet).

## Anti-goals

- Any user value reaching CSS unvalidated (CSS injection via `style`).
- Classes generated by interpolation that Tailwind's `@source` scan cannot see.
- A change that needs a CSS rebuild before a saved block looks right.

## Approaches (picked: A)

- **A. CSS variables + fixed classes (picked).** Values are written as custom properties on the element
  (`style="--ocms-pt:37px; --ocms-pt-md:…"`) and read by literal classes kept in lookup tables
  (`pt-(--ocms-pt) md:pt-(--ocms-pt-md) lg:pt-(--ocms-pt-lg)`). Tailwind sees every class; per-breakpoint works; no
  rebuild on save; fits the existing literal-lookup-table rule.
- B. Per-node generated stylesheet injected at render. Enables hover/animation but adds a CSS generation and SSR
  injection pipeline. Rejected for now (hover is a non-goal).
- C. Store arbitrary Tailwind classes (`p-[37px]`) in the block file and let Tailwind scan them. Needs a rebuild to see
  changes and is hard to validate. Rejected.

## Design

### Values (`@opencloudcms/schema`, pure, shared)

```ts
type Breakpoint = 'base' | 'md' | 'lg';              // mobile (default), tablet ≥768px, desktop ≥1024px
type Responsive<T> = T | Partial<Record<Breakpoint, T>>;
type Length = SpacingToken | 'auto' | `${number}${'px' | 'rem' | 'em' | '%' | 'vw' | 'vh'}`;
type ColorValue = ColorToken | `brand:${string}` | `#${string}`;  // hex: #rgb #rrggbb #rrggbbaa
type Sides = { t?: Length; r?: Length; b?: Length; l?: Length };
type Track = `${number}fr` | 'auto' | Length;          // a column track

interface NodeStyle {
  padding?: Responsive<Sides>;
  margin?: Responsive<Sides>;             // 'auto' allowed (centering); negative lengths allowed for margin only
  width?: Responsive<Length>; maxWidth?: Responsive<Length>;
  height?: Responsive<Length>; minHeight?: Responsive<Length>;
  background?: ColorValue; color?: ColorValue;
  borderWidth?: '0' | '1' | '2' | '4' | `${number}px`; borderColor?: ColorValue;
  borderSides?: ('t' | 'r' | 'b' | 'l')[];  // default all four; header uses ['b']
  radius?: 'none' | 'sm' | 'md' | 'lg' | 'xl' | 'full' | `${number}px`;
  hidden?: Partial<Record<Breakpoint, boolean>>;
}
```

- Spacing tokens are unit-less (`'8'`) and custom lengths always carry a unit, so the two never collide; a token
  renders as `calc(var(--spacing) * N)`.
- Validation uses strict regexes (number + whitelisted unit; hex; brand name `^[a-z][a-z0-9-]{0,31}$`); numbers are
  bounded (lengths ≤ 10000, tracks ≤ 12 per breakpoint, `fr` 1–12). Invalid values fail spec validation with a path.
- A plain (non-object) value means "all breakpoints".

### Columns

Children of Columns and Grid get `span?: Responsive<1..12 | 'full'>` (footer intro spanning both columns on
mobile) in their style.

`Columns` gets `tracks?: Responsive<Track[]>`, `alignY?: 'start'|'center'|'end'|'stretch'`, `gapX?`, `gapY?`
(Length). Old `count: 2|3|4` stays valid and is the fallback when `tracks` is absent (same classes as today). Children
fill tracks in order and wrap to new rows. Missing breakpoints are filled from the smaller one when serialising,
so every emitted `--ocms-cols*` variable is defined.

Presets shown in the panel (custom editor next to them): 1 · 1:1 · 1:2 · 2:1 · 1:1:1 · 1:2:1 · 1:1:1:1 ·
`auto | 1fr | auto` ("logo · fill · actions") · `1fr auto`. Default for a new Columns: base `[1fr]`, md `[1fr 1fr]`.

The library page block `Columns` gets the same `tracks` field (preset select + custom), keeping `columns` as fallback.

### Brand colors and palettes

`src/theme.ts` in a project, managed like `src/locales.ts` (rewritten by the admin in dev, read-only in production):

```ts
export default defineTheme({
  colors: { surface: { label: 'Surface' }, feature: {}, ink: {}, accent: {}, 'accent-ink': {}, line: {} },
  palettes: {
    olive: { label: 'Cream & olive', values: { surface: '#fbf8ef', feature: '#ece9d7', ink: '#28291e', accent: '#3d462c', 'accent-ink': '#fffdf4', line: '#cfcab9' } },
    clay:  { label: 'Cream & clay',  values: { /* … */ } },
    night: { label: 'White & forest', values: { /* … */ } },
  },
  activePalette: 'olive',
});
```

- Every palette must define every color (validated); a theme with one palette is the simple case.
- `ThemeStyle` (from `@opencloudcms/core/blocks/next`) renders `:root{--ocms-color-surface:#fbf8ef;…}` for the
  active palette; the site layout and the admin builder/page-builder canvas both include it. `brand:x` renders
  `var(--ocms-color-x)`, so switching palettes recolors everything without touching blocks.
- Admin: a Page builder > Theme screen to edit colors/palettes and pick the active one (dev-only writes, same queue
  and snapshot/restore as blocks); the builders' toolbar has a palette preview switch that changes only the canvas.
- The admin receives the theme the same way it receives the blocks (`AdminWithBlocks`), lists brand colors in the
  color picker after the semantic tokens, and warns (does not crash) on a `brand:` name the theme lacks.
- Text on a colored background is not auto-switched for brand/custom colors (only semantic tokens keep their
  paired foreground); the panel offers the text color right below background.

### Rendering (`@opencloudcms/core/blocks` `ui`)

`styleProps(style: NodeStyle | undefined): { className: string; style: CSSProperties }` builds the variables and picks
literal classes from new lookup tables (one class per property per breakpoint, emitted only when set). `hidden`
uses `hidden` / `md:block` style display classes per breakpoint (the element's own display is restored, e.g. `flex`
or `grid`). All `ui` layout primitives and the composed renderer accept an optional `style` prop and merge it after
their token classes through `cn` (tailwind-merge), which drops the token class of the same property, so custom values
win (Tailwind sorts `h-(--ocms-h)` before `h-9`; `test/blocks/style-css-order.test.ts` compiles every primitive × style
property to check the `--ocms` rule wins). fr tracks render as `minmax(0,<n>fr)`, like `grid-cols-N`. A Box/Card
without padding seeds its default padding (`py-8` / `p-6`) into `style.padding` on the first padding edit, and shows
it as placeholders. The isomorphic rule (no hooks/browser globals) still holds.

Which style sections each element gets:

| Element | Spacing (pad/margin) | Size | Colors & border | Hide |
|---|---|---|---|---|
| Box, Stack, Columns, Grid, Card | ✓ | ✓ | ✓ | ✓ |
| Image | margin only | width/height | — | ✓ |
| Button | margin only | width/height | ✓ (background, text color, border, radius) | ✓ |
| Badge | margin only | width/height | text color | ✓ |
| Heading, Text, Price, Date | margin only | max-width | text color | ✓ |
| Divider, Spacer, Slot | margin only | — | — | ✓ |

Image also gets `fit: 'cover'|'contain'` and height `100%` support so it fills a column (hero).

Stack also gets `justify: 'start'|'center'|'end'|'between'` and `wrap` (header nav needs space-between).

### Builder panel (admin)

- A device toggle in the builder header (Mobile 375 / Tablet 768 / Desktop 1280) resizes the canvas and sets the
  breakpoint the style panel edits. Inherited values show greyed with the breakpoint they come from; a reset
  clears the override.
- Sections, collapsible: **Layout** (columns preset strip + track editor, align, gaps), **Spacing** (box-model
  widget: outer margin ring, inner padding ring, linked/unlinked sides), **Size**, **Colors & border**
  (swatches: semantic, brand, then a hex input with picker), **Visibility** (hide on mobile/tablet/desktop).
- Each value field: token select first, a "Custom" choice opens a number + unit input. All labels in the 4 locales.
- The page builder uses the same color/spacing/track field components for library blocks that expose them.

### Compatibility and versioning

New props are optional; specs without them render byte-identical classes. Adding style props is not a breaking
change to a composed block. Ejected (code) blocks call `styleProps` the same way.

## Constraints

- Puck 0.24.1 pinned; Tailwind v4 (`bg-(--var)` syntax); literal classes only; `@opencloudcms/schema` stays free of
  `node:*`; blocks dual ESM/CJS build; 4 admin locales; existing test suites stay green.

## Decisions settled during review (builder's calls, marked)

1. **Where style lives:** a new optional `style?: NodeStyle` on `ComposedNode`, sibling of `props`. Not bindable to
   data or block fields. In Puck it is one custom field `style` per element. *(call)*
2. **Old token props:** Box/Card `padding` and `background` and Columns `count` keep rendering exactly as today.
   When the builder edits a node that has an old prop, it converts it into `style` (`padding: '8'` → `style.padding
   {t:'8', b:'8'}` for Box, all sides for Card; `count: 3` → `tracks: ['1fr']` at
   base and 3×`1fr` at md) and drops the old prop, so a node never has both. The semantic `background` prop is kept (it carries its paired
   foreground); a style background, when set, replaces it. Stack `direction` becomes responsive. Files are only
   rewritten when saved. *(call)*
3. **Canvas breakpoints:** both builders already render in Puck's iframe, so `md:`/`lg:` respond to the iframe
   width. The device toggle uses Puck `viewports` (375 / 768 / 1280) and also sets the breakpoint the panel edits. *(call)*
4. **Grid:** keeps its current `sm`/`lg` classes and gets no `tracks`; Grid children's `span` uses base/md/lg. *(call)*
5. **Theme plumbing:** the project imports `src/theme.ts` itself (as with `locales.ts`); `AdminWithBlocks` gains a
   `theme` prop; dev writes go through a new `PUT /api/system/theme` on the existing `SchemaWriteQueue` with
   snapshot/restore and `schemaEditable` gate; `<ThemeStyle theme={theme} />` is added by hand to the my-store site
   layout and to the project scaffold template. *(call)*
6. **Tailwind scan:** every new class is a literal in the `ui` lookup tables, so the existing `@source dist/blocks`
   finds it; a unit test asserts each table value is a literal class string. *(call)*
7. **Library `Columns` page block:** gets a `tracks` field (preset select + custom, max 6 tracks) and slots
   `column1`..`column6`; composed Columns allow up to 12 tracks and children wrap into new rows. *(call)*
8. **Mockup gaps:** Image gets `aspect?: Responsive<'auto'|'square'|'video'|'3/2'|'4/3'|'wide'>` and `fit`; the
   header's `5%` padding is a custom `%` length; Stack gets `justify`, `wrap`, `align`; Box gets none of these. *(call)*
9. **Negative margins:** custom lengths may start with `-` only in `margin`, enforced by validation; tokens are never
   negative. *(call)*
10. **Acceptance:** the my-store rebuild is built through the builders (seeded as composed block files + page data),
    checked functionally in the smoke test and by a side-by-side screenshot review at 375 / 768 / 1280 against the
    mockup; no pixel diff. *(call)*

## Breakpoints vs the mockup

The mockup's 760px and 420px rules map to `md` (768) and `base`; the 421–767 range uses the base values. Accepted.
